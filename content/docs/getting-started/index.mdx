# Quickstart

This is the one path from a new account to your first run and its evidence.
Everything it skips (writing actors, tuning checks, interviews) is a tutorial
of its own, linked at the end.

<PageFacts
  items={[
    { label: "Time", value: "About 5 minutes" },
    { label: "Who", value: "Anyone in a workspace" },
    { label: "You need", value: "A URL an actor can reach" },
  ]}
/>

<Steps>
<Step>

### Create a workspace

Sign in with the six-digit code sent to your email, or continue with Google.
Stunt Double then asks you to create a **workspace** for your team. If a
colleague's workspace accepts your email domain, you can join it instead.

</Step>
<Step>

### Tell it what to test

Enter your product's URL. Stunt Double reads the site, writes actors for the
people who use it and picks the flows worth checking first, as checklists in
your first **project**. It takes a couple of minutes, and the project also
gets a first agent readiness score from the
**[Stunt Double Index](/index-ranking)**.

No URL yet? Choose **I don't have a URL yet** and describe the product and who
it is for instead. The checklists wait, and run as soon as you add a URL to the
project.

<Screenshot
  name="dashboard"
  alt="A project in the Stunt Double dashboard: the sidebar lists interviews, comments, checklists and automations, beside the project's checklists and their latest results."
  caption="A project's home. Everything you create from here on lives inside it."
/>

</Step>
<Step>

### Watch your first run

When setup finishes, choose **Watch your first run**. An actor opens a hosted
browser and works through the first checklist while you watch. To run any
other checklist, open it from **Checklists** and press **Run**.

</Step>
<Step>

### Read the evidence

Every run is recorded. Open the finished run to see each check's result with
the screenshot the actor took and its explanation, then replay the session if
you need more. Failed checks also wait for you on the project's **Issues**
page.

<Screenshot
  name="checklist-run"
  alt="A finished checklist run: two checks passed and one failed, with the failed check open to show its screenshot and the actor's explanation."
  caption="A failed check opens on the moment it failed, with the actor's reasoning beside the screenshot."
/>

</Step>
<Step>

### Add a check of your own

Open **Checklists**, choose **Create checklist** and pick a template or
**Start from scratch**. Write each check as a plain-language outcome, such as
"Confirm the Pro plan shows a monthly and an annual price", choose the actor
and URL, then create the checklist and press **Run**. The actor works out the
clicks.

<Screenshot
  name="checklist-editor"
  alt="A checklist being edited, with three plain-language checks listed in order and a Run button."
  caption="One check per outcome. The actor works out the clicks."
/>

</Step>
</Steps>

<Callout variant="note" title="Testing a site inside your network?">
  A hosted browser can't reach a site that is only available inside your
  network. On the Startup plan and above, a Mac in your workspace runs those
  checks instead. See
  **[Devices](/integrations/self-hosted-workers)**.
</Callout>
