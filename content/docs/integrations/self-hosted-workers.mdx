# Devices

Your staging site sits behind a VPN, so a cloud browser cannot reach it. A
device is a Mac running the Stunt Double app, inside your network. Actors set
to run on it browse with that Mac's Chrome, its VPN, its internal DNS and its
saved sign-ins. The app connects out to Stunt Double, so you open no inbound
ports.

For a full walkthrough, read
[Test a product behind your firewall](/tutorials/self-hosted-worker).

## What it does

- **Reach internal products.** Actors on a device open staging, intranet and
  local dev servers, the same way the person at that Mac can.
- **Outbound only.** The app connects to Stunt Double. Nothing connects in.
- **Domain controls.** Each device can be limited to the domains actors need.
- **Mixed workspaces.** Actors set to the cloud keep using Stunt Double's
  cloud browser, so one workspace can use both.

## Before you start

- **Plan.** Devices are part of the Enterprise plan. On other plans,
  **Settings**, then **Devices**, explains what they do and how to upgrade.
  You see the same prompt when you point an actor at an address that only
  works inside a network.
- **Role.** A workspace owner or admin turns devices on. Once they are on, any
  member can set up their own Mac.
- **A Mac.** macOS on Apple silicon or Intel, with Google Chrome installed,
  that can reach both the product you want to test and `app.stuntdouble.io`.

## Set it up

1. **Turn devices on.** An owner or admin opens **Settings**, then
   **Devices**, and switches on **Use devices in this workspace**.
2. **Install the app.** On the Mac, download the
   [desktop app](/integrations/desktop-app), open it and sign in.
3. **Set up this Mac.** Open **Go**, then **This Device** (Cmd+D), and click
   **Set up this Mac**. The device console shows **Connected** once the Mac
   checks in, and the Mac appears under **Settings**, then **Devices**.
4. **Choose where each actor's browser runs.** Open an actor, go to its
   **Manage** tab and find **Where this actor's browser runs**. Choose one of:
   - **Stunt Double cloud**, for public sites.
   - **Any device in this workspace**, to use whichever device is online when
     a run starts.
   - **A named device**, to always use that Mac.

To check a device can reach a site before a run depends on it, enter the
address under **Test connection** in **Settings**, then **Devices**. The test
runs in the device's browser, so a pass means actors can reach that address.

## How runs pick a browser

The same rules apply however a run starts: the Run button, an automation, the
MCP server, the Figma plugin, the assistant, Slack, Linear or an interview.

- **An actor set to a device never runs in the cloud.** If its device is
  offline, or no device is online for an actor set to any device, the run
  stops and says so. It does not fall back to a cloud browser.
- **A cloud actor never opens an internal site.** If the project is marked
  internal, or the address only works inside a network (a private IP range,
  for example), the run stops up front and asks you to choose a device for
  the actor.

## Move a Mac to another workspace

A Mac belongs to one workspace at a time. To move it, open the workspace you
want it in, then open **This Device**. The console shows that the Mac is paired
with another workspace. Click **Move to** and confirm. Runs in the old
workspace stop using it from then on.

## Control what it can reach

Each device has an **Access** setting under **Settings**, then **Devices**:

- **Allow all domains.** The default. The device may reach any host.
- **Allow specific domains.** Only the hosts you list, and their subdomains.
- **Block specific domains.** Any host except the ones you list, and their
  subdomains.

The setting applies to every request the browser makes, including redirects,
popups and page resources, not only the addresses an actor types. On a network
where reach matters, switch to **Allow specific domains** and list only what
actors need. The workspace policy under **Settings**, then **Security**,
applies on top.

## Remove a device

Remove the Mac from **Settings**, then **Devices**. Actors set to it go back
to the Stunt Double cloud. To stop a Mac without removing it, click **Disable
this device** in its device console.

## Troubleshooting

**The device shows Offline.** Open the Stunt Double app on that Mac. A device
is online only while the app is running and checking in. If the app is open
and the console says **Not reaching Stunt Double**, check the Mac is online
and has outbound HTTPS to `app.stuntdouble.io`, then click **Reconnect**.

**The console says "This device is no longer paired".** The device was removed
from the workspace, or its key no longer works. Click **Pair again**.

**A run says devices need the Enterprise plan.** Devices are part of the
Enterprise plan. Contact us to upgrade.

**A run says devices are turned off.** Your workspace is on Enterprise, but
devices are switched off. An owner or admin can switch them on in
**Settings**, then **Devices**.

**A run says the address needs a device.** The actor runs in the cloud, but
the site only works inside your network. Choose a device for the actor on its
**Manage** tab.

**A run says the browser was suspended by security software.** Something on
the Mac, most likely endpoint security, froze Chrome before it could start.
Ask your IT team to allow Stunt Double to launch Google Chrome.

**A run says the browser profile is in use.** Only one Chrome can use the
device's profile at a time. Close any Chrome window still open on that
profile, such as a sign-in window, and try again. A browser left behind by an
earlier session of the app is closed for you.

**A run says the address is not permitted.** The device's **Access** setting,
or the workspace policy in **Settings**, then **Security**, blocks that host.
Add it to the allowed list or remove it from the blocked list.
