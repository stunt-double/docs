# Devices

Your staging site sits behind a VPN, so a cloud browser cannot reach it. A
device is a Mac running the Stunt Double [desktop app](/integrations/desktop-app),
inside your network. Actors that run on it browse with that Mac's Chrome, its
VPN, its internal DNS and its saved sign-ins. The app connects out to Stunt
Double, so you open no inbound ports.

This page is the reference: setup, how runs choose a browser, network access,
admin controls and troubleshooting. To test an internal site once, end to end,
follow [Test a product behind your firewall](/tutorials/self-hosted-worker).
To watch and steer an actor on your own Mac instead, start a
[live session](/tutorials/live-sessions) on **This Mac**: it pairs the Mac for
you in the background.

The desktop app is the only way to run a device. The older command-line and
Docker workers have been retired.

## What it does

- **Reach internal products.** Actors on a device open staging, intranet and
  local dev servers, the same way the person at that Mac can.
- **Outbound only.** The app connects to Stunt Double. Nothing connects in.
- **Every kind of run.** Checklists, interviews, ideas, design reviews,
  crawls of a project's pages and actor chat all use a device when the site
  needs one, however they start.
- **Domain controls.** Each device can be limited to the domains actors need.
- **Mixed workspaces.** Public sites keep using Stunt Double's cloud browser,
  so one workspace can use both.

## Before you start

- **Plan.** Devices are on every paid plan, for public sites. Private and
  internal addresses (staging behind a VPN, an intranet, a local dev server)
  need the Startup plan or above. Pointing an actor at one of those on another
  plan shows what is needed and how to upgrade.
- **Role.** Any member can set up their own Mac. Testing, restricting and
  removing a device, and pooling devices, take an owner or admin.
- **A Mac.** macOS 10.15 or later on Apple silicon or Intel, with Google
  Chrome installed, that can reach both the product you want to test and
  `app.stuntdouble.io`.

There is no switch to turn devices on. They are on wherever the plan includes
them, and nothing runs on one until a run needs it.

## Set it up

1. **Install the app.** On the Mac, install the
   [desktop app](/integrations/desktop-app#install-it), open it and sign in.
2. **Set up this Mac.** Open **Devices** from the sidebar (or **Go**, then
   **This Device**, Cmd+D). In the app, **This Mac** sits at the top of the
   page. Click **Set up this Mac**. It shows **Connected** once the Mac checks
   in, and the Mac joins the list under **Macs**.
3. **Point actors at it, if you want.** An actor on the cloud browser already
   borrows a device for internal sites (see
   [How runs pick a browser](#how-runs-pick-a-browser)). To keep an actor on a
   device for every run, open the actor, go to its **Browser** tab, choose
   **Device**, then pick **Any device in this workspace** or a named Mac.

The browser runs inside the app by default, and you watch it under **Live
view** on This Mac. If a site asks for a client certificate, Keychain or a
smart card, switch **Where the browser runs** to **Its own window** (see
[How the browser runs](/integrations/desktop-app#how-the-browser-runs)). If
the product sits behind a VPN portal or SSO, open the browser under **Live
view** and sign in once: the sign-in persists for later runs.

To check a device can reach a site before a run depends on it, open the
device from **Devices** and enter the address under **Test a URL**. The test
opens it in the device's browser, so a pass means actors can reach that
address.

### Device status

A device shows its status live everywhere it appears: the **Devices** list,
an actor's **Browser** tab and **This Mac** in the app. It reads
**Connected**, **Running a task** or **Offline**. A Mac that stops checking in
turns **Offline** within a couple of minutes, so you can tell before starting
a run that depends on it.

## Internal projects

Stunt Double works out whether a project's address is public or internal when
you save it. As you type the address, the form says whether actors will open
it in the cloud or on a device. An owner or admin can override it in the
project's **Settings**, under **Network**, with **Reached from**: **Public
internet** or **Internal network**.

## How runs pick a browser

The same rules apply however a run starts: the Run button, an automation, the
MCP server, the Figma plugin, the assistant, Slack, Linear or an interview.

- **A cloud actor borrows a device for an internal site.** If the project is
  internal, or the address only works inside a network (a private IP range,
  for example), the run takes whichever device is online. If none is, it stops
  up front and says so rather than failing in a cloud browser. `localhost` is
  the exception: it means one particular Mac, so only an actor set to that
  device opens it.
- **An actor set to a device never runs in the cloud.** If its device is
  offline, or no device is online for an actor set to any device, the run
  stops and says so. It does not fall back to a cloud browser.
- **Runs sharing a device take turns.** A device runs one browser at a time,
  oldest run first. A run waiting its turn stops at once if the device goes
  offline, or after an hour in line. With several Macs online, runs go to the
  one with the shortest queue.
- **Internal addresses need Startup.** Below the Startup plan, a run to a
  private or internal address stops, on a device as well as in the cloud.
- **Cancelling frees the device.** Cancel a run from its report and the device
  is free for the next one straight away.

## Pool devices

When someone sends Stunt Double's Slack or Linear agent a link only your
network can reach, it opens on that person's own Mac. Under **Sharing** on the
**Devices** page, an owner or admin can switch on **Pool devices** so any
connected Mac in the workspace can open it, the sender's own first. One
always-on Mac can then cover the whole team. While it is off, each person's
links open on their own Mac only.

## Move a Mac to another workspace

A Mac belongs to one workspace at a time. To move it, open the workspace you
want it in, then open **Devices** in the app. **This Mac** says the Mac is set
up for another workspace. Click **Move to** followed by the workspace's name
and confirm. Runs in the old workspace stop using it from then on.

## Control what it can reach

Open a device from **Devices**. Under **Network access**, **Sites actors can
open** has three settings:

- **No restriction.** The default. Actors on the device can open any site.
- **Only these domains.** Only the domains you list, and their subdomains.
- **Any domain except these.** Any site except the domains you list, and their
  subdomains.

The setting applies to every request the browser makes, including redirects,
popups and page resources, not only the addresses an actor types. On a network
where reach matters, switch to **Only these domains** and list only what
actors need. The workspace policy under **Settings**, then **Security**,
applies on top.

## Remove a device

Open the device from **Devices** and click **Remove device**. Actors pinned to
it go back to the Stunt Double cloud. To stop a Mac without removing it, click
**Disconnect** on **This Mac** in the app.

## Troubleshooting

### Messages on This Mac

**The device shows Offline.** Open the Stunt Double app on that Mac. A device
is online only while the app is running and checking in. If the app is open
and **This Mac** says **Not reaching Stunt Double**, Stunt Double has not
heard from it for over a minute: check the Mac is online and has outbound
HTTPS to `app.stuntdouble.io`, then click **Reconnect**.

**This Mac says "No browser found on this Mac".** The device drives Chrome.
Install Google Chrome, reopen **Devices** and click **Set up this Mac**.

**This Mac says it is no longer paired.** The device was removed from the
workspace, or its key no longer works. Click **Pair again**.

**This Mac says it is set up for another workspace.** See
[Move a Mac to another workspace](#move-a-mac-to-another-workspace).

**This Mac says "Update the desktop app".** That version cannot run a device.
Restart the app to finish the update that installs in the background.

### Errors on runs

**A run says no device in this workspace is online.** The site is internal,
so the run needs a device. Open the Stunt Double app on a Mac in that network
and set it up.

**A run says it needs a device, which is included on every paid plan.**
Upgrade from **Settings**, then **Billing**.

**A run says private URLs need the Startup plan.** Private and internal
addresses need Startup or above, whether the actor runs on a device or in the
cloud. Upgrade from **Settings**, then **Billing**.

**A run says devices are turned off.** Devices have been switched off for
your workspace. Contact hello@stuntdouble.io to turn them back on.

**A run says the browser was suspended by security software.** Something on
the Mac, most likely endpoint security, froze Chrome before it could start.
Ask your IT team to allow Stunt Double to launch Google Chrome.

**A run says the browser profile is in use.** Only one Chrome can use the
device's profile at a time. Close any Chrome window still open on that
profile, such as a sign-in window, and try again. A browser left behind by an
earlier session of the app is closed for you.

**A run says the address is not permitted.** The device's **Network access**,
or the workspace policy in **Settings**, then **Security**, blocks that host.
Add it to the allowed list or remove it from the blocked list.

## Custom deployments

If the Mac app does not fit how your network works, for example you want the
relay running in your own cloud, the Enterprise plan includes custom
deployments. Contact hello@stuntdouble.io to talk it through.
