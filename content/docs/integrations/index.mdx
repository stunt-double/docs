# Integrations

A design gets updated in Figma, a pull request opens on GitHub, a preview
lands on Vercel. Each of those is a moment when someone should try the flow
before it ships. Integrations let Stunt Double act at that moment instead of
waiting for someone to remember to start a run.

Actors drive real browsers through real products and report back with
evidence. Anything with a reachable URL can be tested: production, staging, a
Vercel preview, a published Figma Make prototype, a Claude design artifact or
a v0 link. Integrations decide when that happens and where the results land.

## How Stunt Double plugs in

Three mechanisms connect Stunt Double to your other tools:

1. **The MCP server** at `https://app.stuntdouble.io/api/mcp`. Any MCP client
   (Claude, Claude Code, Cursor, Windsurf, ChatGPT and others) gets the full
   toolset: create and run checklists, launch persona interviews, triage
   feedback and comment on pull requests. Client setup lives in the
   [MCP section](/mcp).
2. **Connections and event triggers.** Connect GitHub, Vercel, Cursor Origin,
   Figma or Slack and automations can start on pull requests, deploys, design
   updates and Slack messages, so checks re-run without anyone asking. Slack
   and Linear also bring an agent your team can ask directly.
3. **The dashboard** at [app.stuntdouble.io](https://app.stuntdouble.io), for
   anything visual: watching session recordings, reading interview reports and
   managing actors and integrations.

## How every connection works

Every integration lives on the **Integrations** page of your workspace, which
you open from the sidebar. It lists them in two sections: **Plugins**, which
install Stunt Double into the tools you already work in (Claude, ChatGPT, the
Cursor plugin, the Figma plugin and other MCP clients), and **Platform
integrations**, the services the workspace connects to. **Custom MCP servers**,
your own systems for actors to use during a run, are listed below them.

Each row shows whether it is connected. An integration you have not connected
yet has a **Connect** button right on its row, so you can start without
opening it. Click a row to open its page. Each platform integration is set up
in the same three steps, in the same order, so learning one teaches you all of
them. The exception is [Cursor Origin](#cursor-origin), which is installed
straight onto the workspace.

1. **Your account.** Click **Connect** followed by the tool's name (for

   site. The step then reads **Connected as** with your account name, and
   lists the workspaces already using it.
2. **Your workspace.** The second step carries your workspace's name and a
   switch. An owner or admin turns it on, and the step reads **On for this
   workspace.** Members see **Off. Ask a workspace owner or admin to turn it
   on.** until an admin does.
3. **Projects.** Click **Choose for a project** and pick a project. That opens
   the project's **Settings**, on the **Integrations** tab, where you choose
   the design file, repository, Linear team, Slack channel or Vercel project
   it works with. If the workspace has no projects yet, the button reads
   **Create a project**.

Once an integration is on, its page grows a **Settings** section for anything
that applies to the whole workspace, such as GitHub's watched repositories or
the Linear agent's identity.

<Callout variant="note" title="One account, several workspaces">

  as many workspaces as you like, and each one shows up on step one as a place
  the connection is used.
</Callout>

### Disconnecting

To remove a connection, open the integration and click **Disconnect** on the
**Your account** step. A dialog titled **Disconnect** followed by the tool's
name lists every workspace that loses the integration. Confirm, and those
workspaces stop using it until someone connects again.

To stop one workspace from using a connection while others keep it, an owner
or admin turns off the switch on step two instead. Slack works a little
differently: see [Slack](/integrations/slack) for **Remove** versus
**Disconnect**.

### Handing setup to someone else

GitHub, Linear and Slack each show an **Install link** card at the foot of
their page. Copy the link and send it to whoever should finish setup: a
teammate who owns the GitHub organization, or an admin who has to flip the
workspace switch. The link walks them through every step for that workspace
and picks up wherever they left off.

## Every integration

| Integration                                      | What it does                                                                              | Who sets it up                                                             |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| [GitHub](/integrations/github)                   | Actor pull request reviews, PR comments, automations on GitHub events                     | Anyone connects; an owner or admin turns it on                             |
| [Vercel](/integrations/vercel)                   | Automations on deployment events, runs against the latest preview, protected previews     | Anyone connects, or install from the Vercel Marketplace                    |
| [Cursor Origin](#cursor-origin)                  | Automations on Origin pull requests, results as Origin check runs and comments            | Any member installs it; an owner or admin removes it                       |
| [Figma](/integrations/figma)                     | Design context for actors, automations on file events                                     | Anyone connects; an owner or admin turns it on                             |
| [Figma plugin](/integrations/figma-plugin)       | Design reviews, checklists, feedback and actor chat inside Figma                          | Each designer, from Figma                                                  |
| [Linear](/integrations/linear)                   | The Stunt Double agent on Linear issues: reviews, runs and answers                        | Anyone connects; an owner or admin turns it on and picks the agent's actor |
| [Slack](/integrations/slack)                     | Design reviews in threads, notifications, a workspace agent in direct messages            | An owner or admin adds it to the workspace                                 |
| [Webhooks](/integrations/webhooks)               | Start an automation from any system that can send an HTTP request                         | Anyone who can edit automations                                            |
| [Feedback widget](/integrations/feedback-widget) | Collect comments on your live site into a project                                         | Project members; owners and admins set workspace limits                    |
| [Devices](/integrations/self-hosted-workers)     | Run actors from a Mac on your own network, against sites the public internet cannot reach | Each member sets up their own Mac, from **Devices** in the sidebar         |
| [Desktop app](/integrations/desktop-app)         | Stunt Double in a Mac window, local tools and models, and the way to make a Mac a device  | Anyone                                                                     |

Each integration's page lists exactly what Stunt Double requests from it, such
as OAuth scopes, and what it uses them for. MCP clients (Claude, Claude Code,
Cursor, Windsurf, ChatGPT) request `mcp:read`, `mcp:write` and `mcp:run`;
their setup is in the [MCP section](/mcp).

## Cursor Origin

Cursor Origin hosts pull requests opened by Cursor agents. Install the Stunt
Double app on Origin and those pull requests can start automations, with the
result reported back on Origin.

- **Connect.** Open **Cursor Origin** under **Integrations** and click
  **Install Cursor Origin**. Choose all repositories or only some, and Origin
  returns you to the page, which reads **On for everyone in this workspace.**
  An install started from Origin itself waits for an owner or admin to click
  **Add to workspace**.
- **Trigger.** Choose **Cursor** as an automation's trigger and pick the
  events: **PR Opened**, **PR Published** (a draft is published), **PR
  Reopened**, **PR Updated** (new commits on the pull request), **PR Closed**
  and **Check Re-run**. An optional repository filter, as
  `owner-slug/repo-name`, limits it to one repository.
- **Results.** Each run reports as an Origin check run, named after the
  automation in a **Stunt Double** check suite, and can be re-run from Origin.
  A **GitHub Comment** step posts on the Origin pull request instead.
- **Access.** The app reads repository contents and pull requests, and writes
  only pull request comments, reviews and check runs. It never pushes code or
  creates branches.
- **Remove.** An owner or admin clicks **Remove** on the workspace step. That
  stops automations and check runs here; uninstall the app in Origin to remove
  it there too.

## Which to connect first

- **Your code ships through pull requests:** connect [GitHub](/integrations/github),
  and [Vercel](/integrations/vercel) if your previews deploy there, so every
  preview is checked and the result lands on the pull request. The
  [codebases guide](/guides/codebases) covers the whole loop.
- **Your agents open pull requests on Cursor Origin:** install
  [Cursor Origin](#cursor-origin).
- **You design in Figma:** connect [Figma](/integrations/figma) for design
  context and file-change triggers, and give designers the
  [Figma plugin](/integrations/figma-plugin).
- **Your team lives in Slack or Linear:** add [Slack](/integrations/slack) or
  [Linear](/integrations/linear), so people can ask for a review or a run
  where they already talk.
- **Your CI deploys somewhere else:** call a [webhook](/integrations/webhooks)
  at the end of the deploy.
- **Your product is behind a firewall:** set up a
  [device](/integrations/self-hosted-workers) with the
  [desktop app](/integrations/desktop-app).
- **You want comments from real visitors:** install the
  [feedback widget](/integrations/feedback-widget).

The **[guides](/guides)** cover what to do once you are connected.
