# Desktop app

The desktop app is Stunt Double in its own Mac window. It can also make your
Mac a [device](/integrations/self-hosted-workers), so actors browse with this
computer's Chrome, including its VPN access and machine-credential sign-ins,
and it runs [live sessions](/tutorials/live-sessions) in a browser on your
Mac, with MCP servers and models from this Mac.

## Before you start

- **macOS.** macOS 10.15 or later, on Apple silicon or Intel.
- **Chrome.** Google Chrome installed, if you want to use the Mac as a
  device. [Set up this Mac](#set-up-this-mac) can install a separate Chrome for
  Testing for live sessions instead.
- **Plan.** The app itself works on any plan. Using the Mac as a device needs
  a paid plan, and testing private or internal addresses from it needs the
  Startup plan or above. There is no switch to turn devices on: any member can
  set up their own Mac.

## Install it

1. Go to [stuntdouble.io](https://stuntdouble.io) and click **Download for
   Mac**.
2. Open the download and drag Stunt Double into **Applications**.
3. Open the app and sign in with your Stunt Double account.

The app updates itself. It checks when it launches, when it wakes from sleep
and when you come back to it, so a Mac that is never quit still gets the
latest version. To check straight away, choose **Stunt Double**, then **Check
for Updates…**.

## Use this Mac as a device

1. In the app, open **Devices** from the sidebar, or **Go**, then **This
   Device** (Cmd+D). **This Mac** sits at the top of the page.
2. Click **Set up this Mac**. It shows **Connected** once the Mac checks in.
   Below it, **Live view** shows the browser as actors use it, beside an
   activity log that never leaves this Mac.
3. Runs on internal projects can now borrow the Mac. To keep an actor on it
   for every run, open the actor, go to its **Browser** tab, choose **Device**,
   then pick this Mac or **Any device in this workspace**.

Setting up is remembered. When the app restarts, including after an update,
the Mac reconnects by itself. Quitting the app closes its browser.

To stop, click **Disconnect** on **This Mac**. A run already in progress stops
with it.

A live session does not need this step: starting a session on **This Mac**
pairs the Mac in the background when it is not a device yet.

### How the browser runs

Under **Browser**, below **This Mac**, **Where the browser runs** sets how the
browser appears, for runs and for [live sessions](/tutorials/live-sessions)
alike:

- **Inside the app** (the default). The browser has no window of its own. You
  watch it in the app and can take control when you need to.
- **Its own window.** A real Chrome window on your desktop. Slower to work
  alongside, but the only way to answer a client certificate, Keychain or smart
  card prompt.

Both share one browser profile, so a sign-in done in either is available to
both. Sign-ins you make persist for later runs. You cannot switch while a task
is running.

## Set up this Mac

Live sessions on this Mac can use a few optional extras. Open them from the
app menu, **Stunt Double**, then **Set Up This Mac…**, or from **Tools and
models** on **This Mac**.

| Package                 | What it adds                                                  |
| ----------------------- | ------------------------------------------------------------- |
| Chrome for Testing      | A clean browser for sessions, kept apart from your own Chrome |
| Node                    | MCP servers that start with `npx` or `node`                   |
| uv                      | Python MCP servers that start with `uvx` or `uv`              |
| Local models (Ollama)   | Running the actor on a model on this Mac                      |

Each row says whether the package is already here and its size. Click
**Install** and the app asks you to confirm, naming the package, its size and
where it comes from, before it downloads anything. Every download is checked
against a published checksum before it is unpacked, and everything installs
into `~/.stuntdouble` in your home folder: nothing system-wide, and no
administrator password. A Node or uv you already have keeps working, and wins
over the one installed here.

## Local models

With Ollama installed and running, **Set Up This Mac** suggests models built
for tool use and multi-step tasks, all of which read the actor's screenshots.
The list is ranked by this Mac's memory: the largest model that runs well
alongside the browser is marked **Best fit for this Mac**, and one that needs
more memory than the Mac has says so.

| Model            | Size   | Memory | Notes                                    |
| ---------------- | ------ | ------ | ---------------------------------------- |
| `qwen3.5:4b`     | 3.4 GB | 8 GB   | Small and quick                          |
| `ministral-3:8b` | 6 GB   | 16 GB  | Fast at tool calls                       |
| `qwen3.5:9b`     | 6.6 GB | 16 GB  | A good all-rounder for multi-step tasks  |
| `gemma4:12b`     | 7.7 GB | 24 GB  | Reads pages and screenshots closely      |
| `gemma4:26b`     | 16 GB  | 32 GB  | Steadier on long tasks                   |
| `qwen3.8:27b`    | 18 GB  | 32 GB  | The strongest here at long agentic tasks |

Click **Install** on a model to download it. If you already run Ollama, the app
uses yours and the models you have pulled; otherwise it starts the one it
installed when it is needed, listening only on this Mac, and stops it when you
quit.

To use one, choose it under **Model** when you start a live session on **This
Mac**. When a live session's actor thinks with a model on this Mac, the model never
sees Stunt Double's credentials, and what it reads stays on your Mac. Only the
session's journey, captures and transcript are saved to your workspace, and the
end-of-session summary is built from those facts alone, without sending the
transcript to Stunt Double's model.

  Choosing a local model for a session is in early access alongside live
  sessions.
</Callout>

## MCP servers on this Mac

In a live session on this Mac, the actor can use MCP servers that run on your
Mac. They never run in Stunt Double's cloud. Add them in the app, or import
the ones you already use in Claude Desktop or Cursor from the session's
**Tools**. The app asks you to approve each server, showing the exact command,
before it starts, and editing a server's command switches it off until you
approve it again. See [Tools and sign-ins](/tutorials/live-sessions#tools-and-sign-ins)
for how they work in a session.

## Troubleshooting

**This Mac says "No browser found on this Mac".** The device drives Chrome.
Install Google Chrome, reopen **Devices** and click **Set up this Mac**.

**This Mac says it is set up for another workspace.** A Mac belongs to one
workspace at a time. Click **Move to** followed by this workspace's name and
confirm to move it here. Runs in the other workspace stop using it.

**This Mac says "This Mac is no longer paired".** The device was removed from
the workspace, or its key no longer works. Click **Pair again**.

**This Mac says "Not reaching Stunt Double".** The app is running, but Stunt
Double has not heard from it for over a minute. Check the Mac is online, then
click **Reconnect**.

**This Mac says "Update the desktop app".** That version cannot run a device.
Updates install in the background, so restarting the app is usually enough.

**A run says the browser was suspended by security software.** Endpoint
security on the Mac froze Chrome before it could start. Ask your IT team to
allow Stunt Double to launch Google Chrome.

**A run says the browser profile is in use.** Only one Chrome can use the
device's profile at a time. Close any Chrome window still open on that
profile, such as a sign-in window, and try again.

**An install in Set Up This Mac fails.** Check the Mac is online and try again.
A failed install leaves any earlier version in place.

**A Mac MCP server will not start.** Its command may need Node or uv. The
server's row in **Tools** says what is missing and links to **Set Up This
Mac**.
