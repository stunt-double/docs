# Integration guides

Stunt Double's core offering is simple: **AI user personas (actors) that drive
real browsers through real products and report back with evidence**. Anything
with a reachable URL can be tested: production, staging, a Vercel preview, a
Figma Make published prototype, a Claude design artifact, a v0 link.

That means Stunt Double is not a destination you visit; it is a validation
layer that plugs into wherever the work already happens. These guides show how
to wire it into the most common workflows so that testing and research happen
automatically, at the moment a design or change exists, rather than as a
separate chore afterwards.

## The integration model

Three mechanisms make Stunt Double feel native in other tools:

1. **The MCP server** (`https://app.stuntdouble.io/api/mcp`). Any
   MCP-compatible agent (Claude, Claude Code, Cursor, Windsurf, custom agents)
   gets the full toolset: create and run checklists, launch persona
   interviews, triage feedback, comment on PRs. The server ships workflow
   prompts (`validate_design`, `verify_change`, `run_user_research`,
   `triage_feedback`, `setup_guardrails`) that appear as slash commands in
   most clients. See the **[MCP server](/support/docs/api/mcp)** reference for
   setup.
2. **Connections and event triggers.** Workspace connections (GitHub, Figma,
   Linear, Slack, Vercel) let workflows fire on GitHub, Figma, Vercel, Linear,
   and Slack events, so checks re-run on pull requests, deploys, and design
   updates without anyone asking.
3. **The dashboard** ([app.stuntdouble.io](https://app.stuntdouble.io)) for
   anything visual: watching session recordings, reading interview reports,
   managing actors and connections.

## Guides by workflow

- **[Claude design](/support/docs/integrations/claude-design)**: design an
  artifact in Claude, publish it, validate with personas, and iterate in the
  same chat.
- **[Figma](/support/docs/integrations/figma)**: test prototypes with
  personas, re-check flows automatically on file updates, and put brand
  guardianship on autopilot.
- **[Figma Make](/support/docs/integrations/figma-make)**: publish the Make
  site, interview personas against it, and feed findings straight back into
  the next iteration.
- **[Codebases](/support/docs/integrations/codebases)**: verify changes on
  preview deployments from Claude Code, Cursor, or GitHub, and report results
  on the pull request.

## Where each role feels it

- **Designers** get usability findings while the design is still cheap to
  change: persona interviews against prototypes, with transcripts and evidence
  instead of hunches.
- **Product managers** get research at decision speed: a structured study
  (brief, discussion guide, varied personas, synthesised report) in minutes,
  plus feedback triage that clusters and reproduces what users report.
- **Engineers** get a user-level regression net: checklists that exercise real
  flows on preview deployments, results as PR comments, and event-triggered
  re-runs on deploys.
- **Leadership** gets continuous confidence: scheduled guardrail workflows
  over the critical paths (signup, checkout, core value action), with failures
  reaching Slack or Linear rather than support tickets.
