# Stunt Double documentation

You ship a change on Friday and find out on Monday that sign-up broke. Stunt
Double finds that first. You create **actors**, AI personas that drive a real
browser through your product, and give them work: **checklists** that verify a
flow, **interviews** that report how a persona got on, and **workflows** that
run both on a schedule or on every deploy. Every run comes back with a
recording, screenshots and the steps behind each result.

## How the pieces fit together

A **workspace** holds your team. Inside it you create **projects**, and inside
a project you create **actors**. An actor has instructions and knowledge, and
can drive a real browser and read email.

Once you have an actor, you give it work:

- A **checklist** walks a flow in a hosted browser and reports what passed or
  failed, with the evidence for each check.
- An **interview** runs a structured study with persona participants and
  produces a report you can act on.
- A **workflow** chains steps into an automation that runs on a schedule, on a
  webhook, or on events from GitHub, Linear, Figma or Vercel.

A project can also collect **comments** from the people reviewing your work.
Add the feedback widget to a prototype, staging build or live site and
stakeholders pin comments on the page, each with a screenshot and page context.
See **[Collect stakeholder feedback on a prototype](/support/docs/tutorials/feedback-widget)**.

<Callout variant="tip" title="You don't need to start in the dashboard">
  Connect **[Slack](/support/docs/integrations/slack)** and a link shared with a
  request for feedback is reviewed in the thread it was posted in. See **[Review
  designs from Slack](/support/docs/tutorials/slack-design-review)**. Or connect
  an assistant through **[MCP](/support/docs/mcp)** and ask it to run a
  checklist.
</Callout>
